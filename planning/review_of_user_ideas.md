## 3. 文档中我判定为不可直接执行或需修正的地方

以下均已用附件真实数据核实，不是推测。

### 3.1 【主要问题】第 5 页 ILR 变换：在本题数据上不可直接执行

文档建议：

> 对 p 做 ILR 变换到 16 维欧氏空间，再建模 Loss。**零比例用小伪计数并做敏感性。**

**实测结果**（`scratch/check_ideas_claims.py`、`scratch/check_zero_pattern.py`）：

| 文件 | 行数 | 精确零的个数 | 含零的行 | 每行零个数（中位） |
| --- | --- | --- | --- | --- |
| `train_mixture_1m.csv` | 512 | 3928 | **511 / 512** | 约 8 / 17 |
| `test_mixture_1m.csv` | 256 | 1871 | 255 / 256 | — |
| `test_mixture_1B.csv` | 64 | 360 | **64 / 64** | 约 5 / 17 |
| `est_mixture_10b/70b.csv` | 63 | 487 | 63 / 63 | — |

零值不是零星现象：**512 行里 511 行至少有一个域为精确 0**，每行中位数约 8 个域为 0，
最多 15 个域同时为 0。`train_mixture_1m` 的 top-3 域质量中位数 0.879，
即配方高度稀疏且集中。

**为什么这否掉了 ILR**：ILR 建立在对数比之上，要求分量严格为正。
当每行中位有 8 个零时，伪计数 ε 不再是「小扰动」——`log ε` 会成为一个由人工选定的大负数，
**并且主导该行在 16 维空间中的坐标**。敏感性分析无法挽救这一点，因为结论会系统性依赖 ε 的取值。
文档把它当作一个小的敏感性事项处理，**低估了严重程度约一个量级**。

**建议的替代**（留待方法卡定，不在此预设）：
直接在单纯形上建模并显式处理零（如零膨胀结构、或把「域是否启用」与「启用后占比」分开），
或采用不要求正分量的约束回归。HD-2=B 声明的 baseline（带单纯形约束的线性回归）**不受影响**，
因为它不做对数比变换。

### 3.2 【结构性后果】第 8 页 D_eff 形式隐含恒定弹性比，影响可辨识性

文档建议的广义形式：

$$D_{eff} = D\,Q^{\gamma}e^{b^{T}z_p},\qquad L = E + AN^{-\alpha} + BD_{eff}^{-\beta}$$

这个设计本身是合理的（质量提升等价于更多有效 Token，Q=1 且 z_p=0 时退化为经典式，
满足题目「Q=1 时退化」的可选约束）。但它有一个文档没有指出的代数后果：

$$\frac{\partial L}{\partial Q}\cdot\frac{Q}{L} \Big/ \frac{\partial L}{\partial D}\cdot\frac{D}{L} = \gamma \quad \text{（恒等于 }\gamma\text{，与 } N, D, Q \text{ 无关）}$$

**已数值验证**：在 N ∈ {1e8, 1e10} × D ∈ {1e9, 1e11} × Q ∈ {0.4, 0.8} 八个点上，
该比值恒为 2.0000（设定 γ=2.0），无一例外。

两个后果：

1. **Q 与 D 的替代率被结构性地固定为常数**。这与第 9 页自己的风险栏
   「等价关系随 N、D、Q 所在位置变化，不能写成固定比例」**部分矛盾**——
   在这个具体形式下，Q↔D 的弹性比确实是固定的（只有 Q↔N 会随位置变化）。
   论文若同时写这两句话会自相矛盾。
2. **可辨识性**：沿 Q 方向，数据只能识别乘积 βγ，无法单独分离 β 与 γ。
   因此 **β 必须先由真实 N-D 数据（B1）钉住**，再用含 Q 的 B6–B8 估计 γ。
   若同时自由估计 β 和 γ，会得到一条退化的等价参数脊。
   这一点对 Q2 的参数估计顺序有直接约束。

**处置**：不否定该形式（它仍是合理候选），但列为 Q2 方法卡的**必查项**，
并把「β 先由 B1 钉住」写入实现约束。

### 3.3 【需要纠正的细节】四个无 Loss 列的域恰好是最常为零的域

**实测**（`scratch/check_zero_pattern.py`）：在 `train_mixture_1m` 中，
最常为零的 6 个域里有 4 个正是**没有 Loss 列**的域：

| 域 | 为零的行数 | 是否有 Loss 列 |
| --- | --- | --- |
| `enron_emails` | 352 / 512 | ❌ 无 |
| `philpapers` | 306 / 512 | ❌ 无 |
| `nih_exporter` | 297 / 512 | ❌ 无 |
| `hackernews` | 269 / 512 | ✅ 有 |
| `europarl` | 264 / 512 | ❌ 无 |
| `ubuntu_irc` | 252 / 512 | ✅ 有 |

在 `test_mixture_1B` 中同一模式更明显（enron_emails 62/64 为零）。

**这不是巧合**：RegMix 很可能对不参与评测的域系统性地压低了配比。
这一发现改变了「4 个无 Loss 列域如何处理」的答案倾向——它们在配方中本就多为 0，
直接影响「保留 / 合并 / 正则化 / 仅解释间接影响」四个选项的代价对比。
文档完全没有提到这个域—零值的关联。**这是我们比文档多掌握的一项事实。**

### 3.4 【轻微】第 2 页的分位数标准化与「不能各表单独归一」

文档第 2 页给出 `z = (x − Q₀.₀₅)/(Q₀.₉₅ − Q₀.₀₅)`，并在风险栏正确指出
「若 A1/A2/A3 分别归一化，域级 Q 不可直接比较」。这条是对的，我已登记。

但要注意：A2 仅 arxiv、A3 仅 github，**两者各自只覆盖一个域**。
若用「A1+A2+A3 合并后统一求分位数」，则 A3 的 203752 条 github 记录会主导全局分位数
（占合并总样本的 74.9%）。所以「统一转换规则」还需附加一条：
**分位数应在哪个总体上计算**——合并全体、还是按域分别、还是以 A1 为参照系。
文档没有讲到这一层。**已登记为数据画像阶段必须定的口径。**
